How we work

  • Tests first, seen failing; the test-auditor's red pass, then the code

  • A decision goes into docs/decisions.md at once

A change, from the plan to main

1 · PLAN

/slice-plan writes the slice's plan in docs/plans/; Alexis approves it.

2 · TESTS FIRST

Failing tests, seen failing; the test-auditor's red pass, named on a Red-pass: line. Then the code.

3 · EACH COMMAND AND EDIT

guard.py: no git hook skipped, no forced push, no gnokey or raw chain call, no .gno before the gno skill. Then the permissions, the sandbox.

4 · END OF EACH TURN

The Stop hook ends the turn only once the fast gate passed on exactly this tree. It runs nothing from the repository.

5 · EACH COMMIT

commit-msg: a conventional subject of 72 characters, no attribution, no secret or private name. pre-commit: the staged files scanned; in the sandbox, the fast gate on a copy of them, recorded.

6 · PUSH OF A BRANCH

pre-push: the checked-out commit, nothing uncommitted; a gate passed on its code; the whole history scanned.

7 · /PRE-MERGE

The full gate, /simplify, then every review lens below; each finding verified and reproduced into the ledger; the full gate on the final code; the pass recorded.

8 · ALEXIS

Reviews in revdiff, blind first, with the review card; then merges in his own shell. Claude never merges or pushes.

9 · PUSH OF MAIN

pre-push, in Alexis's shell: no gate runs; the full gate recorded on this code, its review pass, each harness change declared.

10 · THE CI

GitHub runs the full gate again on every branch pushed: read-only, no secret, every action and tool pinned.

The gate · scripts/check.sh, and the net that never shrinks

Fast: each turn, commit and branch push (60 s at most; about 25 s)

  • Prettier; tsc, where core sees no DOM and no Node
  • ESLint: floating promises, swallowed errors, any, an import across a boundary (core imports only core), cycles, size, an impure core, switched-off tests, CSS
  • On the app: React's hooks and compiler rules, no hand-written memo, no raw HTML
  • Vitest, core's and the app's: a test with no assertion fails
  • knip and jscpd: dead code and copies
  • CUBE CSS and comment rules
  • The app built, pre-rendered and walked by Playwright with axe; a build that edits a package file fails
  • gno lint, gno test; each realm guard removed must fail a test
  • Go: gofmt, go vet, the seal vectors
  • Docs name real files; the ledger's rows; each test beside its file; every script parses
  • test_hooks.sh: the hooks, the guard, the settings, the CI's promises

Full: /pre-merge and a push of main add (about 4.5 min)

  • probe.py: each rule still catches its planted fault
  • Coverage 85% everywhere, 100% in core; 85% of the lines the branch changed
  • prove_fix.py: a fix's test or journey failed on the commit before it
  • StrykerJS: the TypeScript's mutants
  • check_regressions.py: the net, at the right
  • gitleaks over the history; pnpm audit
  • harness_mutate.py, when a harness file changed

Reviews and findings

The review pass of /pre-merge, sized by risk

test-auditor Red pass before the code; green pass first in /pre-merge, on the mutation survivors (Sonnet)
/simplify Every merge, first: reuse, simplicity, efficiency, altitude; then the gate again
/code-review Every merge, in a fresh context: correctness, performance, accessibility and UX
/security-review Every merge; keeps only what it rates 8 out of 10 or more
security-reviewer Also on a tier-1 file, with the project's threat model (Opus)
finding-verifier Each tier-1 lot of findings: refutes, then reproduces (Opus)
gno-auditor Every realm, read line by line
Alexis Blind first, in revdiff; the card's tier-1 files, tests, how to try it, each realm function's card

Rounds converge, as Anthropic's do: from the second, only the new diff; after three, stop and reconsider the approach. Each finding names its class, and its fix covers every instance.

A finding's life, in docs/review/findings.md

claimed→verifier: refute, then reproduce→reproduced→fixedrejectedintendedmootasked
  • Reproduced: a command's output, or a test seen failing
  • Fixed: its commit, a Finding: line, the test that failed before it
  • Rejected (wrong), intended (wanted) or moot (of no matter): each with its reason; never raised again
  • Asked: Alexis decides; the decision goes into docs/decisions.md
  • A miss seen twice becomes a rule, a lint or a test
  • docs/review-log.md: what each review caught and missed, and its false alarms

Security boundaries

The sandbox, around every shell command

  • Writes only in the project and its caches, never in the harness's files
  • Reaches only the npm and Go registries and github.com
  • No command may leave it; ~/.ssh, ~/.config/gh, ~/.npmrc, ~/.aws unreadable

Permissions (.claude/settings.json)

  • Asks only before a git push and a chain write
  • Refuses any edit of a file run outside the sandbox: the git hooks and the scripts they run, the guard, the Stop hook, Claude Code's settings, agents, commands, skills, rules and hooks, the package files, pnpm-workspace.yaml, .npmrc, a pnpmfile
  • Refuses pnpm add and rm -rf; .env and deploy/secrets/ unreadable

Secrets and privacy: the repository will be public

  • gitleaks on what is staged, the whole history and every commit message
  • Two rule sets, both always run: secrets, and what must not be named (a home folder, the host's services)
  • gitleaks:allow and a root .gitleaksignore do not count
  • No key is ever pasted in a chat; secrets live in gitignored files, read through *_FILE

Supply chain

  • pnpm takes packages a day old at least, no trust downgrade, no pnpmfile, no install script
  • A dependency is Alexis's to add; pnpm audit in the full gate
  • prepare runs the system's git, never one planted in node_modules
  • A build that edits package.json or the lockfile fails the gate

The CI (.github/workflows/gate.yml)

  • Read-only permissions, no secret, credentials not kept
  • Actions pinned by commit, gitleaks by checksum, gno by commit
  • The frozen lockfile, installed with no install script; Chromium's headless shell
  • Reports on every push; cannot yet block a merge

The chain

  • Everything about gno goes through gnomcp; the guard refuses gnokey and raw RPC
  • Keys and mnemonics never enter the conversation
  • Every chain write asks Alexis; mainnet is read-only
  • gno is pinned by commit to the chains' release line (v1.5.1)

The harness proves itself

  • probe.py: one planted fault per lint rule and check, named by its own message
  • test_hooks.sh: each hook and script on throwaway repositories
  • harness_mutate.py: each guard switched off in turn must fail a test
  • mutate.py, StrykerJS: the realms' and the TypeScript's mutants
  • prove_fix.py: a fix counts once its test failed without it
  • check_regressions.py: no test gone, no floor lower, unless a commit says why
  • A new guard lands with its planted fault and its mutant

Known limits

  • The CI reports but cannot block a merge on this plan (next: main protected, with code owners)
  • A record of a green gate can be forged from the sandbox: a broken tree reaches main until the CI's red report, and nothing runs on Alexis's machine
  • A branch planted through git's plumbing carries its own hooks into a merge (next: the hooks outside the repository, F129)
  • The history scan is defence in depth: merges, type changes and gitleaks's default paths escape it; the staged scan is the barrier
  • The guard is a pattern list: a seatbelt, not a wall
  • The review pass is recorded by the agent that ran it; the round limit is a written rule
  • prove_fix.py takes any failure before the fix as proof, a crash included
  • No reviewer is scored yet on bugs it should find (next: the reviewers' exam)
